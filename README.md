# Лабораторная работа №1 · Схема и целостность данных

Настольное приложение для учёта экспериментов по ИИ-модерации текста.

## Запуск

Скачайте или клонируйте репозиторий и откройте его папку в терминале.

Нужны Python 3.12, запущенный PostgreSQL версии 13 или выше и роль с правом создавать схемы в выбранной базе. Для чистого запуска подойдёт локальная база `postgres` или отдельная учебная база. Дистрибутивы для macOS, Windows и Linux доступны на [сайте PostgreSQL](https://www.postgresql.org/download/).

**macOS и Linux**

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m lab01
```

**Windows PowerShell**

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m lab01
```

В окне приложения введите адрес, порт, имя базы, имя роли PostgreSQL и пароль. Адрес `localhost` и порт `5432` подходят для локального PostgreSQL со стандартными настройками.

1. Нажмите **Подключиться**.
2. Нажмите **Создать схему и таблицы**.
3. Нажмите **Добавить демонстрационные данные**.
4. Откройте **Показать данные** и выберите инструмент работы.

Приложение использует схему `moderation_lab1`. При стандартной структуре создание схемы и загрузку примеров можно повторять. Меняйте структуру в выбранной лабораторной. Если переименуете базовые таблицы или поля, верните исходные имена для дальнейшего использования сводки и готовых форм ввода.

Конструкторы выводят до 1000 строк. Загруженные результаты можно сортировать по заголовкам столбцов и фильтровать по тексту. Пароль вводится при подключении. События и ошибки записываются в `database-labs.log`.

## Возможности

- [Схема PostgreSQL](database_labs/schema.sql) содержит строки, целые и дробные числа, булевы значения, даты и время, ENUM и массив меток. В таблицах заданы `PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE` и `CHECK`.
- [Модальные окна](database_labs/ui.py) добавляют датасеты, модели и эксперименты и показывают сводку с JOIN. INSERT выполняется с параметрами внутри транзакции. [Код подключения, ошибок и логирования](database_labs/db.py).

## Что показать на защите

1. Создайте схему, загрузите демоданные и откройте сводку. После первой загрузки в ней шесть экспериментов.
2. Выберите тип **Отзывы** и минимальный F1 **0,8**. Останется **Модель BERT** с F1 **0,8920**.
3. Попробуйте добавить модель **BERT Mini** ещё раз. PostgreSQL отклонит запись по `UNIQUE`.
4. Добавьте эксперимент с F1 **1,2**. Сработает `CHECK`. Поле F1, оставленное пустым, покажет нарушение `NOT NULL`.
5. Нажмите **Проверить внешний ключ и откат**. Приложение попробует сослаться на отсутствующие записи. PostgreSQL отклонит INSERT, а транзакция завершится откатом.
6. В DDL покажите `ON UPDATE CASCADE` для обеих связей, `ON DELETE RESTRICT` для датасетов и `ON DELETE CASCADE` для моделей.
